当个人 Agent 成为新的互联网入口，商业服务也将需要自己的 Agent。

我判断，2027 年可能是 Agent 与 Agent 之间的协作真正开始大规模进入商业场景的一年。

不是因为某个通信协议突然成熟，而是因为互联网正在出现能够长期代表不同利益主体的 Agent，而它们之间需要一种新的协作方式。

这里的 A2A（Agent-to-Agent），我更愿意把它理解为一种交互方式：不同主体的 Agent，围绕目标、约束、方案和承诺进行协商与协作，而不是特指某个协议。

我的判断主要来自两个正在发生的变化：个人 Agent 正在成为新的用户入口，而商业服务不可能因此放弃自己的业务知识与决策权。两股力量的交汇，可能就是下一轮 Agent 生态发展的起点。

## 为什么 A2A 过去没有真正流行起来？

2025 年 4 月 9 日，Google [发布了 Agent2Agent 协议](https://developers.googleblog.com/en/a2a-a-new-era-of-agent-interoperability/)，试图解决不同框架、不同厂商 Agent 之间的通信与协作问题。但在之后相当长一段时间里，至少从我的观察来看，我们并没有看到大量普通用户通过不同 Agent 之间的协作完成实际任务。

我认为，根本原因不是协议设计得不够好，而是当时的基础条件还不成熟。大多数 Agent 连独立完成一项复杂任务都不够可靠，工具调用、环境管理、长任务执行、状态恢复等问题仍未解决。当一个 Agent 都不可靠时，让多个 Agent 互相协作只会放大不确定性。

更重要的是，当时缺少真实需求。用户还在尝试让 Agent 帮自己完成工作，很少有人真正拥有一个能够长期代表自己行动的 Agent。商业服务自然也没有多少动力去专门建设面向 Agent 的协作入口。

协议可以提前标准化，但真实的协作需求无法靠协议创造。

## 个人 Agent 正在成为一种新的互联网入口

过去一年，Coding Agent 的发展让我有一个很明显的感受：我们讨论的问题正在发生变化。

早期，大家关注的是 Agent 能不能写代码、能不能调用工具。现在，很多讨论已经转向如何让 Agent 持续执行更长的任务，如何管理它的运行环境，如何在失败后恢复，以及如何让它更少依赖人的实时干预。

这不代表 Agent 已经足够可靠，可以完全独立工作。但至少在一些领域，它已经从一个演示性质的工具，逐渐成为可以承接实际工作的执行者。

接下来一个重要变化正在发生：Agent 将从用户主动启动的工具，逐渐变成能够持续工作的个人代理。

2026 年 9 月 8 日，Meta [发布了 Muse](https://about.fb.com/news/2026/09/introducing-muse-personal-ai-agent/)；9 月 29 日，OpenAI [发布了 Dots](https://openai.com/index/introducing-dots/)。这类产品值得关注的，并不只是模型能力，而是它们所代表的产品形态：拥有独立的云端计算环境，能够记住用户的偏好、持续推进用户交代的任务，并在必要时回来征求确认。这是它们的产品方向与官方能力描述，并不意味着持续执行的可靠性已经得到普遍验证。

当 Agent 具备这些条件后，它就不再只是一个调用工具的客户端，而更接近一个可以持续行动的数字代理。

这里真正可能改变的，是用户习惯。

过去，我需要订一张机票，就会打开航空公司的 App；需要安排日程，就打开日历；需要购买商品，就去电商平台搜索。未来，我可能只需要向自己的 Agent 描述目标。它知道我的偏好，掌握我的日程，了解我的预算，并且可以在我不在线时持续推进任务。当遇到需要我决策的事情时，它再回来征求意见。

这种方式一旦形成习惯，会带来一个非常重要的结果：

**用户与商业服务之间，开始多出一个长期存在、代表用户利益的中间层。**

过去，服务商需要说服用户打开自己的 App。未来，服务商可能需要先说服用户的 Agent，为什么应该选择自己的服务。

这可能成为互联网流量入口的一次重要变化。

## 商业服务不会主动交出自己的业务判断权

如果个人 Agent 逐渐成为用户访问互联网的新入口，那么接下来就有一个问题：商业服务应该如何与这些 Agent 交互？

最直接的答案是开放 API。查询商品、查询库存、创建订单、支付、取消订单。把这些接口提供给外部 Agent，由它们完成组合调用。对于大量确定性的操作来说，这完全没有问题。

但一家商业服务真正的价值，通常不只是它提供了哪些功能，而是它知道如何利用这些功能解决客户的问题。

以旅行服务为例。真正有价值的，不是能够查到某个航班的信息，而是知道在这个用户的偏好、预算、时间约束以及现有供应商关系下，如何给出一个可接受的方案。这背后包含大量业务经验、内部规则、资源关系和产品设计。对于一家成熟的商业服务来说，这些恰恰是它长期积累的竞争优势。

如果外部 Agent 需要面对的是一个目标不完全明确、需要反复澄清和调整的复杂需求，那么仅仅提供一组固定功能接口，往往意味着把大量业务理解和方案设计工作转移给外部 Agent。谁来决定什么方案更适合用户？谁来解释方案之间的差异？谁有权限调整条件，或者提出新的选择？

如果这些工作全部由用户的 Agent 完成，那么商家就可能逐渐失去与用户共同定义解决方案的机会。长期来看，商业服务甚至可能被压缩成一个个可替换的资源供应方。

我不认为大部分有竞争力的商业服务会甘愿接受这种位置。它们更可能选择保留自己的业务判断能力，并通过某种能够理解外部需求、提出方案、接受委托的服务代理参与协作。

这不一定意味着每家公司都要运行一个独立的大模型。服务代理也可以由规则引擎、工作流、API 和模型共同组成。关键在于，它能够在企业授权的边界内，对外代表这项服务进行业务交互。

个人 Agent 代表用户的利益，服务 Agent 代表企业的能力和商业边界。

双方不需要共享全部内部信息，也不需要服从同一个决策系统。它们需要的是找到一个彼此都能接受的结果。

## 从调用功能，到协商结果

假设我告诉自己的 Agent：

> 帮我安排一次去东京的旅行，预算 8000 元以内，尽量选择直飞，酒店交通方便。如果价格差不多，希望行程可以灵活调整。

按照传统的系统集成方式，我的 Agent 需要分别调用航空公司、酒店和其他服务的 API，查询数据，然后自行理解业务规则、比较价格和制定方案。

但如果服务商也拥有自己的 Agent，情况可能不同。下面是一个设想中的协作过程。

我的 Agent 可以直接向航空公司的 Agent 提出目标和约束。航空公司的 Agent 根据内部库存、定价策略、会员权益和退改规则，给出一个或多个方案，并解释方案之间的区别。如果我更关心灵活性而不是最低价格，个人 Agent 可以继续协商，询问是否存在更合适的组合。酒店及其他服务也可以采用类似方式。

最终，个人 Agent 负责根据我的利益做出选择，服务商的 Agent 则负责在自身业务能力和授权范围内提供方案。

这与传统 API 调用的区别，不是有没有使用自然语言。即使双方通过结构化消息通信，也完全可以实现这样的协作。真正的区别在于：

**过去，我们主要告诉软件执行什么操作；未来，我们可能开始向另一个主体描述希望达到什么结果。**

前者的核心是功能调用，后者的核心是目标协商与任务委托。

当然，如果一个任务只需要确定性的查询或操作，API 仍然是更合适的选择。没有必要为了 A2A 而 A2A。只有当业务存在多种可行方案、信息不完整、约束需要澄清，或者双方需要持续协作时，服务 Agent 才可能体现出相对于直接 API 调用的额外价值。

我认为这会是 A2A 最先建立商业价值的地方。

## 为什么我认为转折点可能在 2027 年？

我并不认为技术发展存在某种必然的年度节奏。2025 年出现协议、2026 年出现云端 Agent，并不能直接证明 2027 年就一定会爆发。

但如果观察最近发生的变化，已经出现了几个值得重视的信号。

首先，个人 Agent 的产品形态正在走向持续执行。无论是 Coding Agent 向长任务发展，还是 Muse、Dots 这类常驻云端的个人代理，都在尝试让用户从“每次主动使用 AI”，转向“把工作持续委托给 AI”。这个变化决定了需求侧是否真正存在。

其次，商业平台已经开始认真接纳外部 Agent。

2026 年 1 月 11 日，Google 与 Shopify 等企业[推出了 Universal Commerce Protocol（UCP）](https://blog.google/products/ads-commerce/agentic-commerce-ai-tools-protocol-retailers-platforms/)，尝试标准化 Agent 与商业系统之间从商品发现到购买及售后支持的交互。它[支持 API、MCP 和 A2A 等通信方式](https://developers.googleblog.com/under-the-hood-universal-commerce-protocol-ucp/)，也允许商家保留自身的业务要求与交易规则。

更近的一个信号发生在 2026 年 10 月 13 日。根据 [The Verge 的报道](https://www.theverge.com/news/1010365/shopify-opens-its-catalog-up-to-more-ai-agents)，Shopify 宣布进一步向第三方 Agent 开放其商品目录和购买能力，不再局限于特定合作伙伴的 Agent。用户可以配置自己的 Agent，并在购买时进行确认。

这些变化目前更多是把商品和交易能力开放给外部 Agent 调用，还不是完整的跨企业目标协商。但重要性在于：商业平台开始把外部 Agent 当作一个需要正式支持的服务入口，而不只是一个技术演示。

过去，互联网产品考虑的是如何让用户进入自己的应用。现在，一些商业平台已经开始考虑如何让外部 Agent 带着用户的需求进入自己的交易体系。

这两个变化一旦形成规模，就可能产生连锁反应。个人 Agent 的用户越多，商家支持这一入口的动力就越强。支持 Agent 协作的服务越丰富，个人 Agent 能完成的任务就越多。用户因而更愿意把工作交给 Agent。

我判断，2027 年可能是这一正反馈开始加速的年份。

但这个判断是有条件的。如果到 2027 年，我们看到个人 Agent 形成稳定的日常使用习惯，不再只是偶尔被调用的聊天工具；看到更多头部商业服务正式支持外部 Agent 发现、委托与交易；同时看到跨服务任务能够完成真正的业务闭环，而不只是演示协作过程，那么我会认为 A2A 正在进入爆发阶段。

反过来，如果个人 Agent 仍然缺少持续使用的真实需求，或者商家只愿意开放有限的查询接口，不愿提供更深入的任务协作，那么这个时间判断就可能过于乐观。

我更愿意把 2027 年看作一个值得观察的商业化转折窗口，而不是一个确定的技术里程碑。

## 当 Agent 能够代表主体做承诺，问题才刚刚开始

A2A 的难点，最终可能并不在通信。两个 Agent 能够交换消息，与它们能够代表不同组织完成一项商业交易，是两回事。

个人 Agent 说自己获得了用户授权，商家如何验证？服务商的 Agent 提供了某个报价，这个报价有效多久？它是否具有约束力？如果任务失败，双方如何确认责任归属？

这些问题说明，当 Agent 开始代表主体做出承诺时，需要交换的就不只是消息，而是可验证的授权、承诺和执行证据。

Google 在 2025 年 9 月 16 日[发布的 Agent Payments Protocol（AP2）](https://cloud.google.com/blog/products/ai-machine-learning/announcing-agents-to-payments-ap2-protocol)，已经开始尝试通过可验证的授权凭证来处理 Agent 支付中的信任问题。我认为这类基础设施会越来越重要。因为商业服务之间的协作，最终必须落到真实的成本、收益、责任和履约结果上。

如果一个 Agent 不能证明自己被允许做什么，另一个 Agent 不能证明自己承诺了什么，那么双方即使可以流畅地交流，也很难建立真正可靠的商业关系。

这也是为什么我认为 A2A 的发展不应该只关注多 Agent 框架和通信协议。身份、授权、任务状态、交易、计费、审计和争议处理，可能会共同构成下一代 Agent 协作的基础设施。

## 下一代互联网，可能开始连接不同的代理主体

回顾互联网的发展，我们已经习惯了几种交互方式。网站让人能够访问在线信息，App 将大量服务带到了用户手中，API 则让不同软件系统能够直接交换数据、调用能力。

而 Agent 可能带来另一种变化。用户开始拥有能够长期代表自己行动的数字代理。企业则可能拥有能够对外表达自身业务能力、维护商业边界并接受委托的服务代理。不同代理之间不再只是交换数据，还可能围绕目标、约束、报价、承诺与履约结果持续协作。

这里真正改变的，是互联网中的决策关系。

过去，大部分跨应用的业务判断最终由人完成，软件主要负责执行。未来，一部分判断可能由不同主体授权的 Agent 分别完成，再通过协作达成结果。

当然，这不意味着互联网会自动变得更加开放。个人 Agent 一旦成为新的流量入口，也可能形成新的平台壁垒。谁拥有用户的长期信任和委托关系，谁就可能在服务选择中占据更有利的位置。

但无论最终形成怎样的竞争格局，商业服务都可能不得不重新思考一个问题：

**当用户不再亲自访问我的产品，而是派一个 Agent 来完成任务时，我应该如何提供服务？**

我认为，这个问题会成为未来几年大量互联网产品需要面对的新课题。商业竞争可能不再只围绕谁能让用户打开自己的 App，还包括谁能让用户的 Agent 更愿意选择自己的服务。服务的可靠性、产品能力、历史履约表现，以及对 Agent 协作的支持程度，都可能成为新的选择依据。

因此，我判断 2027 年将是 A2A 的爆发年。

不是因为 Agent 终于学会了互相说话，也不是因为某个协议即将统一天下。而是因为，当越来越多用户开始拥有能够长期代表自己工作的 Agent，商业服务也需要找到一种方式，代表自己与这些 Agent 打交道。

过去，互联网连接的是人、应用与服务。未来，它可能进一步连接代表不同利益主体行动的 Agent。

我认为，这比 A2A 协议本身更值得期待。
