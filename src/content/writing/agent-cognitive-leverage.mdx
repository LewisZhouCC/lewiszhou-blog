AI 降低了工程工作的执行成本，但企业需要多少工程师，还取决于有价值的任务需求，以及团队能够投入多少理解、判断和验收资源。

最近读了 Anthropic 发布的 [《How employment is changing at Anthropic》](https://www.anthropic.com/research/employment-at-anthropic)。

其中有一个很引人关注的数据：Anthropic 的初级技术人员在技术招聘中的占比，从 2025 年初的 27% 下降到了 9%。

很多人看到这个数据，第一反应是：AI 已经足够强了，未来不再需要初级工程师。

但我读完之后，反而联想到了自己所在团队的一些现实。

我所在团队的资源无法与 Anthropic 相比，但从日常研发来看，AI 算力已经相对充裕。工程师普遍使用 Claude、GPT 等模型，Coding Agent 也已经深入研发流程。

但团队依旧缺少工程师，依旧在招聘初级开发者，甚至实习生。

这让我开始思考一个问题：

**如果 AI 已经可以完成越来越多的工程工作，为什么我们依然需要更多的人？**

我的想法：AI 时代的工程师需求，并不简单取决于 AI 替代了多少工作，而取决于一家企业能够将多少算力转化为真正有价值的成果。

而在这个过程中，人类的认知资源可能正在成为一种新的稀缺生产要素。

## 1. 算力可以扩张，但人类认知能力存在上限

Anthropic 的研究中还有两个很有意思的数据。

到 2026 年 8 月，员工使用的交互式 Agent 的总运行时长已经达到人类工作时长的约六倍。

但与此同时，交互式 Agent 会话约 80% 的墙钟时间处于等待人类输入的状态。

这两个指标的口径不同：运行时长不等于产出，等待人类输入的时间也不是算力浪费比例。

这看起来有些矛盾。

一方面，Agent 已经能够并行处理大量工作；另一方面，人类却越来越难以及时处理这些 Agent 产生的结果和请求。

仔细想想，这其实很符合我日常使用 Coding Agent 的体验。

我可以同时启动五个甚至十个 Agent，让它们分别开发功能、修复 Bug、编写测试、调研方案。

但我真的能同时理解十个任务吗？

当它们陆续提交结果、要求确认、遇到架构冲突或者需要判断业务边界时，我依旧需要逐个切换上下文。

模型的执行能力提升了，但我的理解、判断和注意力并没有同步增长。

这意味着，当算力足够充裕时，限制生产力的因素可能会从执行能力转移到人类认知能力。

这里有一个重要区别：

**单个人类的认知能力存在上限，但一个组织拥有的人类认知资源并不是固定的。**

组织可以通过招聘、任务分工、自动化验证和组织设计，增加整个团队能够同时处理的问题数量。

因此，在某些条件下，增加一名工程师的价值，可能不再主要来自他亲自写了多少代码，而是他能够让多少原本闲置、等待或无法有效利用的 AI 算力转化为可靠的产出。

我暂时把这种能力称为「认知杠杆」：

每投入一小时人类注意力，能够产生多少具有实际价值、经过可靠验收的工作成果。

## 2. 为什么初级工程师仍然有价值？

接下来，我可以尝试把工程工作按照所需能力划分为三个等级。

- **A 类任务**：需要高级工程师承担，例如核心架构设计、复杂系统决策、重大技术风险判断。
- **B 类任务**：需要中级及以上工程师承担，例如常规系统设计、跨模块开发、复杂问题定位。
- **C 类任务**：初级工程师能够独立完成和验收，例如边界明确的功能、标准化修改、具备清晰验收条件的任务。

这里的等级并不是根据代码量或者实现难度划分，而是根据一个人能否对结果承担独立判断和验收责任划分。

在 AI 出现以前，高级工程师同样需要编写大量普通业务代码。

现在，AI 降低了这些任务的实现成本，但没有消除理解需求、验证结果、处理异常所需要的人类认知资源。

假设一位高级工程师每周要花十几个小时处理 C 类任务。

如果这些工作能够由一位初级工程师借助 Agent 独立完成，高级工程师只需要提供少量指导，那么释放出来的时间就可以投入那些只有他才能解决的 A 类任务。

从企业整体来看，这名初级工程师创造的价值，实际上包括两个部分：

一是他直接完成的工作；二是他释放出来的高级工程师产能。

**让高级工程师持续处理低认知门槛的任务，可能是一种昂贵的资源错配。**

当然，这个推论有一个前提：初级工程师必须有能力独立完成并验收这类任务，而且指导成本不能高到抵消他带来的收益。

如果 Agent 已经能够自动完成并可靠验证全部 C 类任务，那么继续为这些任务招聘初级工程师，就可能没有经济优势。

因此，AI 并不天然利好或利空初级岗位。它改变的是不同层级工作之间的分界线，以及不同人员的边际价值。

## 3. 人均生产力提高，不代表企业用人需求必然下降

我还想到一个很有意思的类比。

过去大家都在赛跑，后来我获得了一辆可以喷射起步的 Roadster。

我当然比以前快得多。

但如果竞争对手也获得了一辆 Roadster，我们之间的竞争并不会因此消失。相反，整个比赛的速度和标准都被重新定义了。

AI 对软件行业可能也是如此。

假设工程师的生产力变为原来的三倍，那么完成原本同样数量的工作，理论上确实只需要过去三分之一的人力。

但这里隐含了一个假设：

企业需要完成的工作总量是固定的。

现实中，企业可能还有尚未满足的需求。

一家企业总有很多尚未完成的需求：新的产品方向、过去成本太高而放弃的功能、技术债务、质量改进、用户体验优化，以及还没有被探索的市场机会。

AI 降低了解决问题的成本，也让一部分过去不值得投入的工作变得有经济价值。

如果企业可以持续将这些能力转化为市场竞争力，那么它需要完成的有效任务数量就可能快速增长。

用一个简化的关系表示：

**所需人数 ≈ 有价值的任务需求量 ÷ 人均有效生产力**

如果人均生产力变为原来的三倍，任务需求只变为原来的两倍，那么所需人员可能减少。

但如果任务需求变为原来的五倍，企业反而可能需要更多的人。

所以我不太认同「AI 提高了多少效率，就会减少多少工程师」这种线性推论。

尤其对于仍处于高速增长阶段、还有大量市场机会可以探索的企业，AI 可能同时带来更高的人均生产力和更多的人力需求。

不过，问题本身虽然可以近似认为无穷无尽，真正具有经济价值的问题却不是无限的。

增长能否持续，最终还取决于市场需求、产品价值和企业将产能转化为收入的能力。

而且，Anthropic 本身就是一个反例：它在快速扩张的同时，初级技术招聘占比依然下降。

所以，增长并不能单独决定招聘需求。

我还需要考虑另一个因素：**新增工作究竟分布在哪些能力层级？**

## 4. 一家公司可能存在动态的最优工程师配置

继续前面的 A、B、C 分类。

假设一家企业有三种不同等级的工程师，每个等级的人能够借助 AI 处理不同范围的任务。

那么企业真正需要优化的，就不只是工程师总人数，而是：

高级、中级、初级工程师分别应该招聘多少人，才能使整个组织的产出最大化？

这其实是一个动态最优化问题。

需要同时考虑：

- 不同难度、不同价值的任务分别有多少。
- 不同资历的工程师处理这些任务需要消耗多少认知资源。
- AI 可以替代多少执行工作，又需要多少人工监督。
- 人员薪酬、模型算力、沟通与协作的成本。
- 初级人员的培养成本，以及他们未来晋升所带来的价值。

随着模型能力提升，这些变量都会发生变化。

一部分 B 类任务可能降低为 C 类任务，一部分 C 类任务可能完全交给 Agent 自动完成。

但与此同时，企业也可能因为 AI 获得了新的能力，开始处理过去无法开展的更复杂的 A 类任务。

所以最优人员结构不是固定的。

一家公司的合理配置可能是大量高级工程师搭配少量初级工程师；另一家公司则可能更适合少量架构负责人，搭配一批能够独立管理标准化 Agent 任务的初中级工程师。

这取决于业务模式、任务分布、验证能力和增长速度。

还有一个很容易被忽略的问题：如果企业只追求当前的最优配置，把初级岗位不断压缩，那么几年之后，高级工程师从哪里来？

培养未来的人才，本身也是一项有长期回报的投资。

## 5. 从算力求解成本，重新理解人的价值

沿着这个方向继续思考，我还有一个更抽象的想法。

我能否把每个工程问题理解成一个需要消耗资源才能被解决的任务？

例如，一个问题需要多少模型推理、多少次工具调用、多少轮搜索、多少次重试，才能以足够高的概率获得正确结果？

如果只是重复尝试解决问题，我通常倾向于增加 AI 算力。

但人类认知资源可以改变整个求解过程。

一名高级工程师可能只需要半小时，就能将复杂的问题拆分成几个边界清晰的子问题，再定义出明确的验收标准。

原本需要 Agent 不断试错的工作，可能因此减少尝试次数。

反过来，如果问题有可靠的自动验证器，人类又可以不必逐行理解模型的全部实现，只需要审查验证依据和关键风险。

因此，一个问题不存在脱离工具、验证条件和人类参与方式的唯一「算力求解成本」。

更合理的理解是：**模型算力与人类认知资源共同构成了一条求解成本的权衡曲线。**

有些问题增加算力就能改善结果；有些问题则需要人的判断、真实世界反馈，或者一套更可靠的验证机制。

这也让我觉得，未来一家 AI Native 企业的核心竞争力，可能越来越取决于它能否高效组合这些资源。

我更关心的是，企业能否用更少的人类注意力，更可靠地将 Agent 的工作转化为有经济价值的结果。

## 6. 企业是否也存在一个最适人口密度？

还有一个很有意思的联想，来自种群生态学。

生物学中有一个概念叫[阿利效应（Allee effect）](https://doi.org/10.2307/3547011)。

简单来说，当一个种群数量过少时，个体可能因为难以合作、寻找配偶或获得群体保护而难以增长。增加同类数量，可能改善个体的生存或繁殖条件。

但当种群数量过多时，资源竞争又会限制增长。这属于高密度下的负制约，与低密度下的阿利效应是两种不同的机制。

在同时存在低密度阿利效应和高密度负制约的条件下，种群的人均净增长率可能在中间某个区间最高。

这让我想到，工程师团队是否也存在类似的现象？

这里的「人口密度」只是类比，我讨论的是给定业务范围与协作方式下的团队规模。

当团队只有几个人时，即使拥有大量 AI 算力，也可能因为缺少足够的领域负责人，无法充分利用 Agent 的执行能力。

随着团队扩大，合理分工开始出现。不同工程师能够独立管理各自领域的 Agent，让原本受限于个人认知能力的工作得以并行开展。

但如果团队继续扩大，组织协调、代码集成、沟通和决策的成本又可能逐渐超过新增人员带来的收益。

这与经济学中的规模经济和规模不经济有着相似的逻辑。

不过，人均有效产出最高的规模，未必是企业净收益最高的规模。要判断后者，还需要考虑总产出、人员与算力成本，以及新增产出是否有真实需求。

因此，一家企业对工程师的需求，可能不仅取决于有多少工作需要完成，也取决于它当前处于什么样的组织规模，以及增加一个人究竟能够带来多少边际价值。

Anthropic 减少初级技术岗位的招聘占比，是否部分反映了它当前的组织规模和分工结构？我尚没有足够数据判断。

但这提供了一个值得研究的假说：

**企业的最优工程师人数，以及不同资历工程师的最佳比例，可能都随着 AI 能力、任务需求和当前组织规模动态变化。**

更有意思的是，AI 本身也在不断移动这个最优区间。

它既可以让更少的人组成一个高效团队，也可能让企业以更低的协调成本管理更大的团队。

所以，也许我真正应该研究的不是「AI 会减少多少工程师」，而是「AI 正在如何改变不同规模团队的最优组织结构」。

## 最后

回到最初的问题。

Anthropic 减少了初级技术岗位的招聘比例，而我所在团队仍然在招初级工程师。

这两件事并不一定矛盾。

不同企业有不同的任务分布、增长阶段、AI 自动化程度和组织能力。

对于一家公司来说，AI 可能已经替代了大量适合初级员工承担的工作；对于另一家公司来说，AI 则可能让更多初级工程师具备了独立承担任务的能力，从而帮助企业扩张产能。

我不认为可以因此简单地判断初级工程师将消失，也不应该乐观地认为 AI 一定创造更多岗位。

**AI 降低了执行的成本，但没有自动消除理解、判断、验证和组织协调的成本。**

未来企业真正需要思考的，也许不只是「AI 能够替代多少工程师」，而是：

**当算力越来越充裕时，企业应该如何配置有限的人类认知资源，才能创造最大的价值？**

这可能比预测某个级别的工程师是否会消失，更值得研究。
